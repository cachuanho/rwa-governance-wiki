痛點拆解 ✦ Why Traditional Fails

為什麼讀了那麼多文章，
腦中還是像一盤散沙？

🌪️

資訊未內化，無法跟大腦簡報

看過的文章像過眼雲煙，因為沒有親自把概念「用自己的話講一遍」，真正要向別人報告或自己決策時，腦袋依然一片空白。

🔁

傳統 RAG：永遠在重新發現

NotebookLM 或一般 RAG 只是在問問題時抓片段。每一次提問都在重新檢索，知識永遠不會「跨文件沈澱與累積」。

🏚️

個人筆記難以長期維護

Notion 或 Obsidian 筆記本經常淪為文字墳場。人類受限於精力，難以在每次讀新文章時手動更新 10~15 個關聯頁面。

🧱

概念邊界模糊，缺乏對話辯析

單向閱讀無法檢視自己的理解漏洞。缺少一個隨時在線、能互相推敲法規與商業定義的「費曼對話者」。

系統架構 ✦ Three-Tier System

LLM Wiki 的三層運作結構

🔒

1. 原始來源 (Raw Sources)

真相的基石（唯讀）

存放 PDF、PPTX、報告與法規。LLM 永遠只讀不改，保留不可篡改的客觀事實與歷史版本依據。

🧠

2. 知識庫 (The Wiki)

大腦的持久化延伸

由 LLM 完全維護的 Markdown 資料庫。包含 Source 摘要、Concept 核心概念、Entity 實體，以及全域 index.md 與時序 log.md。

📋

3. 操作規範 (AGENTS.md)

Agent 的靈魂與行為法則

定義如何討論、何時更新索引、Frontmatter 格式與 GitHub Pages 輸出準則，使 LLM 成為高度自律的知識夥伴。

深度比較 ✦ Paradigm Shift

傳統 RAG vs LLM Wiki

比較面向 傳統 RAG（檢索增強生成） LLM Wiki 模式（大腦共創）
知識型態 資料庫中的被動向量碎片（Chunks） 結構化、互相鏈接的 Markdown 知識網
學習機制 問答時臨時拼湊，對話結束即遺忘 經人機討論後持續複利累積
與大腦的關係 搜尋引擎替代品，缺乏心智理解 先向頭腦做簡報，實現真正內化
跨文件矛盾處理 被動輸出可能相衝突的段落 主動在 Concept 頁標註不同來源的爭端與演進
展示與輸出 僅停留在 Chat UI 視窗 同步輸出至 GitHub Pages 互動網頁
流程設計 ✦ Loop & Graph

三大關鍵迴圈（Loop）的運作

📥

Ingest 討論迴圈

1. 讀入新文件
2. 人機對話釐清概念
3. 建立 Source 頁面
4. 跨頁擴充 Concept / Entity
5. 自動更新 Index 與 Log

🔍

Query 輸出迴圈

1. 查閱 index.md 目錄
2. 聚合多份概念與引用
3. 合成教學型簡報結構
4. 優秀成果再回寫 Wiki

🔧

Lint 維護迴圈

1. 掃描孤兒頁面（無連結）
2. 檢測新舊法規矛盾
3. 揪出未定義的重要實體
4. 保持知識網強韌健康

⚡ 設計精髓：把「檢查」節點前移到人機討論階段，杜絕未經消化的死板內容進入知識庫！
